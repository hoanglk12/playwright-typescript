Composition-Based Page Object Model

Favour composition over inheritance for all browser interactions / Ưu tiên composition hơn inheritance cho mọi thao tác trình duyệt
AbstractBasePage → Composed Helpers Architecture
EN

All page objects extend BasePage, which owns 8 specialised helper instances as protected readonly fields. Browser interactions are delegated to helpers. Never call page.locator() or page.click() directly inside a page class. This decouples interaction logic from page semantics and keeps helpers testable and swappable on their own.

VI

Mọi page object đều kế thừa BasePage, lớp này sở hữu 8 helper chuyên biệt dưới dạng field protected readonly. Các thao tác trình duyệt được ủy quyền cho helper. Không gọi trực tiếp page.locator() hay page.click() bên trong một page class. Cách này tách logic thao tác khỏi ngữ nghĩa của page, giúp helper dễ kiểm thử và dễ thay thế độc lập. 

// src/pages/base-page.ts: abstract root of the POM hierarchy
export abstract class BasePage {
  protected page: Page;
  protected readonly waits:    WaitHelper;
  protected readonly elements: ElementHelper;
  protected readonly style:    StyleHelper;
  protected readonly frames:   FrameHelper;
  protected readonly files:    FileHelper;
  protected readonly storage:  StorageHelper;
  protected readonly network:  NetworkHelper;
  protected readonly tables:   TableHelper;

  constructor(page: Page) {
    this.page     = page;
    this.waits    = new WaitHelper(page);
    this.elements = new ElementHelper(page, this.waits);
    this.style    = new StyleHelper(page, this.waits);
    this.frames   = new FrameHelper(page);
    this.files    = new FileHelper(page, this.waits);
    this.storage  = new StorageHelper(page);
    this.network  = new NetworkHelper(page);
    this.tables   = new TableHelper(page, this.waits, this.elements);
  }
}
Locators Hoisted to Class Fields Convention
EN

All Locator instances and raw selector strings must be declared as private readonly class fields at the top of every page class. This keeps selectors discoverable in one place, allows refactors without touching method bodies, and satisfies TypeScript's strict mode. Dynamic (parameter-driven) locators live in private helper methods that reference the field-level constants.

VI

Mọi Locator và chuỗi selector thô phải được khai báo dưới dạng field private readonly ở đầu mỗi page class. Cách này giúp selector nằm ở một nơi dễ tra cứu, cho phép refactor mà không cần đụng vào thân method, và đáp ứng chế độ strict của TypeScript. Locator động (phụ thuộc tham số) được đặt trong các private helper method, các method này tham chiếu tới hằng số ở cấp field.

✅ Correct
class CheckoutPage extends BasePage {
  // Locators as class fields
  private readonly submitBtn =
    this.page.getByRole('button',
      { name: 'Place Order' });
  private readonly itemSel =
    '[data-testid="cart-item"]';

  async placeOrder(): Promise<void> {
    await this.elements.clickLocator(
      this.submitBtn);
  }
}
✅ Đúng
class CheckoutPage extends BasePage {
  // Locator khai báo dưới dạng class field
  private readonly submitBtn =
    this.page.getByRole('button',
      { name: 'Place Order' });

    '[data-testid="cart-item"]';

  async placeOrder(): Promise<void> {

      this.submitBtn);
  }
}
❌ Banned
class CheckoutPage extends BasePage {
  async placeOrder(): Promise<void> {
    // WRONG: inline selector in helper call
    await this.elements.clickElement(
      '[data-testid="submit"]');

    // WRONG: direct page.locator
    await this.page
      .locator('.btn-submit')
      .click();
  }
}
❌ Cấm dùng
class CheckoutPage extends BasePage {
  async placeOrder(): Promise<void> {
    // SAI: selector viết thẳng trong lời gọi helper
    await this.elements.clickElement(
      '[data-testid="submit"]');

    // SAI: gọi page.locator trực tiếp
    await this.page
      .locator('.btn-submit')
      .click();
  }
}
🚫
Banned selectors: Hierarchical structural selectors like div > span > ul > li:nth-child(2) are prohibited. They break on any DOM restructure and carry no semantic meaning. Prefer getByRole(), getByLabel(), getByText(). CSS selectors are only acceptable for computed-style queries (this.style.*) or evaluate() calls.
🚫
Selector bị cấm: Cấm dùng selector cấu trúc phân cấp kiểu div > span > ul > li:nth-child(2). Chúng dễ gãy khi DOM thay đổi cấu trúc và không mang ý nghĩa ngữ nghĩa nào. Ưu tiên getByRole(), getByLabel(), getByText(). CSS selector chỉ chấp nhận cho truy vấn computed-style (this.style.*) hoặc trong lời gọi evaluate().

Custom Fixtures: Playwright Extension Pattern

Page objects and shared utilities injected via test.extend() / Page object và tiện ích dùng chung được inject qua test.extend()
test.extend<CustomFixtures> Design Pattern
EN

src/config/base-test.ts extends Playwright's test with all page objects and utilities. Tests receive page objects via destructuring; no new calls in spec files. Each fixture is instantiated lazily, per test, keeping tests isolated from each other. The use() function marks the setup/teardown boundary: code after await use(...) runs during teardown.

VI

src/config/base-test.ts mở rộng test của Playwright với toàn bộ page object và tiện ích. Test nhận page object qua destructuring, không có lời gọi new nào trong file spec. Mỗi fixture được khởi tạo theo kiểu lazy, cho từng test, giữ các test tách biệt với nhau. Hàm use() đánh dấu ranh giới setup/teardown: đoạn code sau await use(...) chạy trong giai đoạn teardown. 

// src/config/base-test.ts
export const test = base.extend<CustomFixtures>({
  homePage: async ({ page }, use) => {
    await use(new HomePage(page));
  },

  softAssert: async ({}, use) => {
    await use(new SoftAssertHelper(new TestLogger(base.info().title)));
  },

  ecommerceCartOverlayPage: async ({ page }, use) => {
    await use(new EcommerceCartOverlayPage(page));
    // Teardown: Firefox SPA service-worker workaround (see §23)
    if (page.context().browser()?.browserType().name() === 'firefox') {
      await page.goto('about:blank', { waitUntil: 'commit' }).catch(() => {});
    }
  },
});

Factory + Typed Interface Pattern Pattern
EN

All test data lives in src/data/. Every exported constant and generator return type must carry a named interface annotation: never rely on TypeScript inference for exported data shapes. Static constants use const objects; dynamic/random data uses generator classes with explicit return types.

VI

Toàn bộ dữ liệu test nằm trong src/data/. Mọi hằng số export và kiểu trả về của generator phải gắn interface có tên: không dựa vào suy luận kiểu của TypeScript cho các shape dữ liệu được export. Hằng số tĩnh dùng object const; dữ liệu động/ngẫu nhiên dùng generator class với kiểu trả về khai báo rõ ràng.

Interface vs Factory: Two Separate Concepts Clarification
EN

The pattern name "Factory + Typed Interface" names two distinct things working together, not one concept. The interface is only a shape contract: it declares what fields exist and their types at compile time. It creates nothing. The factory is the function or class method that generates dynamic values at runtime and returns a fully populated object satisfying that interface. Defining an interface with typed properties is not the factory; it is only the "Typed Interface" half.

VI

Tên gọi "Factory + Typed Interface" gọi tên hai thứ khác nhau cùng phối hợp, không phải một khái niệm. Interface chỉ là hợp đồng về hình dạng dữ liệu: nó khai báo có những field nào và kiểu gì tại thời điểm biên dịch. Nó không tạo ra gì cả. Factory là hàm hoặc method của class sinh giá trị động lúc runtime và trả về một object đầy đủ, thỏa mãn interface đó. Định nghĩa một interface với các thuộc tính có kiểu không phải là factory; đó chỉ là nửa "Typed Interface".

Interface: shape contract only (compile-time)
// Declares what fields must exist and their types
// Creates NOTHING: no values, no logic
export interface GraTestData {
  validCustomer:    CustomerInput;
  validCredentials: ValidCredentials;
  invalidCartId:    string;
}
Interface: chỉ là hợp đồng shape (compile-time)
// Khai báo field nào phải có và kiểu của chúng
// KHÔNG tạo ra gì: không giá trị, không logic
export interface GraTestData {
  validCustomer:    CustomerInput;

}
Factory: generates values and builds the object (runtime)
// Generate dynamic values first
export function createBrandTestData(prefix: string): GraTestData {
  const email = `${prefix}test${Date.now()}@mail.com`;
  const name  = generateFirstName();
  // Return a REAL OBJECT: all fields use the same values
  return { validCustomer: { email, firstname: name, ... },
           validCredentials: { email, ... } };
}
Factory: sinh giá trị rồi dựng object (runtime)
// Sinh giá trị động trước
export function createBrandTestData(prefix: string): GraTestData {
  const email = `${prefix}test${Date.now()}@mail.com`;
  const name  = generateFirstName();
  // Trả về một OBJECT THẬT: mọi field dùng chung giá trị
  return { validCustomer: { email, firstname: name, ... },
           validCredentials: { email, ... } };
}
ℹ️
Why the factory generates values before the return: all fields for the same logical entity (email, name, address) must share the same randomly generated values. If email were generated separately inside validCustomer and again inside validCredentials, two different Date.now() calls would produce two different emails, and the credentials would no longer match the registered customer.
ℹ️
Vì sao factory sinh giá trị trước khi return: mọi field thuộc cùng một thực thể logic (email, tên, địa chỉ) phải dùng chung giá trị ngẫu nhiên đã sinh. Nếu email được sinh riêng bên trong validCustomer rồi lại sinh riêng bên trong validCredentials, hai lần gọi Date.now() khác nhau sẽ cho ra hai email khác nhau, khi đó credentials sẽ không còn khớp với customer đã đăng ký.

EN

EN
Strict Mode
"strict": true in tsconfig.json. Enables strictNullChecks, noImplicitAny, strictFunctionTypes. CI runs npm run lint (tsc --noEmit); type errors fail the build.
Explicit Return Types
All exported functions and generator methods declare explicit return types. Generator classes return typed interfaces, never inferred types. This prevents interface drift when implementations change.
No any Casts
The AuthType.BEARER enum is always used, never "bearer" as any. Data shapes carry named interfaces. page.evaluate() receives typed arrow functions, not raw strings, wherever avoidable.
Optional Chaining on Error Arrays
gql.errors?.[0]?.message ?? '', even inside a length check. TypeScript does not narrow errors to non-undefined inside if (gql.errors?.length): optional chaining is still required on index access.
Module-Level let Initializers
let cartId: string = '', not let cartId: string. Explicit initializers keep TypeScript's definite-assignment checks unambiguous and make the "empty state" explicit.

EN

All six ecommerce fixtures (ecommerceHomePage, ecommerceNavPage, ecommerceSearchPage, ecommercePLPPage, ecommercePDPPage, ecommerceCartOverlayPage) navigate to about:blank before teardown on Firefox. Root cause: Firefox's Juggler protocol hangs on context.close() when SPAs have active service workers or persistent WebSocket/analytics connections. Navigating to about:blank triggers the unload lifecycle, deregistering service workers and closing connections before the context is destroyed. Do NOT remove this workaround from any of these fixtures.

VI

Cả sáu fixture ecommerce (ecommerceHomePage, ecommerceNavPage, ecommerceSearchPage, ecommercePLPPage, ecommercePDPPage, ecommerceCartOverlayPage) đều điều hướng tới about:blank trước khi teardown trên Firefox. Nguyên nhân gốc: Giao thức Juggler của Firefox bị treo ở context.close() khi SPA còn service worker đang hoạt động hoặc kết nối WebSocket/analytics còn mở. Điều hướng tới about:blank kích hoạt vòng đời unload, hủy đăng ký service worker và đóng kết nối trước khi context bị hủy. Không được gỡ bỏ cách xử lý này khỏi bất kỳ fixture nào trong số này. 

// Fixture teardown (after await use(...))
if (page.context().browser()?.browserType().name() === 'firefox') {
  await page.goto('about:blank', { waitUntil: 'commit', timeout: 5000 })
    .catch(() => {});  // swallow: page may already be closing
}
// Teardown của fixture (sau await use(...))
if (page.context().browser()?.browserType().name() === 'firefox') {
  await page.goto('about:blank', { waitUntil: 'commit', timeout: 5000 })
    .catch(() => {});  // bỏ qua lỗi: page có thể đã đang đóng
}
Firefox User Preferences for Stability Workaround
EN

The Firefox project in playwright.config.ts sets explicit firefoxUserPrefs to disable geolocation, push notifications, background processes, and speculative connections that can cause flaky network waits or test-isolation issues. Network timeouts are also tightened to prevent lingering connections from blocking context teardown.

VI

Project Firefox trong playwright.config.ts đặt tường minh firefoxUserPrefs để tắt geolocation, push notification, tiến trình nền, và kết nối speculative, những thứ có thể gây chờ network không ổn định hoặc vấn đề cô lập test. Timeout network cũng được siết chặt hơn để tránh kết nối còn treo làm nghẽn teardown của context.

Staging Eventual-Consistency Polling Workaround
EN

PLA staging token revocation has a race condition: after revokeCustomerToken, the old token may still be accepted for 1 to 5 seconds. Tests poll the protected resource at TIMEOUTS.POLL_INTERVAL_NORMAL (1s) intervals until the graphql-authorization error appears, instead of asserting immediately after revocation.

VI

Việc thu hồi token trên staging của PLA có race condition: sau revokeCustomerToken, token cũ vẫn có thể được chấp nhận trong 1 đến 5 giây. Test poll tài nguyên được bảo vệ theo khoảng TIMEOUTS.POLL_INTERVAL_NORMAL (1s) cho tới khi lỗi graphql-authorization xuất hiện, thay vì assert ngay sau khi thu hồi.
